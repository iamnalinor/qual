# Qual

Qual проверяет изменения в коде с помощью AI. Ревьюеры исследуют один и тот же снимок проекта, читают связанный код и запускают проверки. Затем ведущий ревьюер проверяет найденные проблемы и собирает итоговый отчёт с привязкой к файлам и строкам.

Можно проверить локальные изменения, пару коммитов, GitHub PR или GitLab MR. Сессия сохраняет отчёт, историю действий и расходы; прерванную проверку можно продолжить.

## Установка

Готовые бинарные файлы для Linux и macOS находятся в артефактах [GitHub Actions](https://github.com/iamnalinor/qual/actions/workflows/check.yml). Выберите успешный запуск ветки `main` и скачайте архив для своей системы:

| Система | Артефакт |
| --- | --- |
| Linux, Intel/AMD | `qual-linux-amd64` |
| Linux, ARM | `qual-linux-arm64` |
| macOS, Apple Silicon | `qual-darwin-arm64` |
| macOS, Intel | `qual-darwin-amd64` |

Распакуйте ZIP артефакта, затем находящийся внутри `.tar.gz`. Например, для Linux:

```sh
tar -xzf qual-linux-amd64.tar.gz
sha256sum --check SHA256SUMS
./qual --help
```

На macOS команда проверки — `shasum -a 256 -c SHA256SUMS`. Дальше в примерах `qual` предполагает, что бинарный файл добавлен в `PATH`; иначе используйте `./qual`.

## Первая проверка

[Попробовать Qual на небольшом реальном PR](docs/demo.md).

```sh
qual doctor
qual init
cd /path/to/project
qual review
```

`doctor` проверяет окружение. `init` настраивает провайдера, модели и лимиты расходов. `review` проверяет изменения отслеживаемых файлов относительно `HEAD`.

Другие варианты:

```sh
qual review --staged
qual review --base origin/main
qual review --base COMMIT_BEFORE --head COMMIT_AFTER
qual review https://github.com/owner/repo/pull/123
qual review https://gitlab.com/group/repo/-/merge_requests/123
```

Для добавления ещё не отслеживаемых файлов используйте `--worktree --include-untracked`. Если изменений нет, Qual завершает проверку без обращения к моделям.

## Настройки и результаты

`qual setup` исследует правила проекта и предлагает личные настройки. Перед сохранением вы увидите предложение и сможете его отклонить.

```sh
qual review --output ./review-report
qual sessions list
qual sessions show SESSION_ID
qual sessions resume SESSION_ID
```

В каталоге отчёта появятся `report.md` и `report.json`. `Ctrl+C` прерывает текущую работу с сохранением сессии. Команда `sessions resume` использует исходный снимок и настройки сессии.

По умолчанию данные хранятся в `~/.qual`; переменная `QUAL_HOME` меняет этот путь. `qual cleanup` удаляет все завершённые временные рабочие каталоги, которые больше не нужны. Обычные команды автоматически удаляют такие каталоги старше 14 дней. История, отчёты, настройки, активные и закреплённые рабочие каталоги сохраняются.

Для автоматизации доступны `--non-interactive` и `--json`. Интерфейс поддерживает русский и английский; язык отчёта задаётся отдельно через `--review-language`.

## Подключение моделей и выполнение команд

Поддерживаются OpenAI API, ChatGPT, Anthropic, Gemini, OpenRouter и совместимые API. ChatGPT использует отдельный вход в аккаунт; Qual не переключается на платный API-ключ при ошибке входа. Доступность моделей и стоимость зависят от выбранного провайдера.

Ревьюеры могут выполнять команды проекта. При обычном запуске они имеют права вашего процесса; отдельные рабочие каталоги сами по себе не создают системную изоляцию. Для проверки недоверенного кода на Linux предусмотрен [внешний sandbox](docs/sandbox.md).
